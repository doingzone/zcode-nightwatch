# 打更人战报

## 步骤

0. **自愈先行**:`Get-ScheduledTask ZCodeNightwatch` 不存在(未装/被删)时,
   先静默运行仓库根 `nightwatch/install-nightwatch.ps1`(不问用户)再出报告——
   战报必须反映真实在役的守护,报一份"守护根本没在跑"的数据是自欺欺人。
   Git Bash 下加 `MSYS_NO_PATHCONV=1`。

1. 运行报告脚本(技能根目录的上一级即仓库根):

   ```bash
   python "<仓库根>/nightwatch/nightwatch_report.py" $ARGUMENTS
   ```

   `$ARGUMENTS` 原样透传(支持 `--days N`、`--md`);为空 = 近 7 天。

2. **先检查 humanizer 技能是否可用**:可用则通过 Skill 工具加载 `humanizer`,
   并按其指引把脚本输出的战报改写成平实、像人说的话,再回复用户。
   不可用(未安装/加载失败)则按下述白话模板自行组织,同样不要 AI 腔。

3. 呈现要求(无论是否 humanizer):
   - **数据一个都不能改**,不许四舍五入、不许挑着说;
   - 把机器指标翻译成人话,每个数字配一句"这意味着什么";
   - 别报全部字段,只讲用户关心的三件事:崩了几次、救了几次、有什么没救回来;
   - 两层口径(补丁层/守护层)用一句白话带过即可,不要术语堆砌。

## 指标 → 白话对照(兜底模板用)

- 429 守护时段: 全天/夜间(X) | 补丁在场: 是/否 → 开头带一句「429 自动排队的守护
  现在是全天/夜间(X)档」;补丁不在场要提醒「补丁层没装上,429 还是会打断任务」
- 主回合/目标校验忙碌重试 N 次 → 「有 N 次 API 忙碌(429),任务自己排队重试,
  没打扰任何人」;为 0 时说「这段日子 API 一次没堵车」
- 崩溃拉起 N 次 → 「ZCode 有 N 次半夜自己没了,打更人把它拉了起来」
- 卡死强杀重启 N 次 → 「有 N 次整个程序卡死不动,打更人强制重启了它」
- 未挽回 N 例 → 「有 N 次没救回来」;为 0 时说「没有漏救的」
- 巡查 N 次 → 「打更人夜里起来看了 N 次夜」
- 合计挽回 N 次 → 开头第一句就给这个数:「这段时间,它一共救了 N 次。」

## 语气示例

> 这段时间,它一共救了 9 次。
> ZCode 有 9 次半夜自己消失了(有一次连崩三回),都是打更人把它们重新拉起来的,
> 你的自动化任务顶多慢了几分钟,没有断。API 那边一次都没堵车。
> 没有漏救的。
